# 字段规则级 ETL 测试（MongoDB）

测试粒度是**一个目标字段上的一条映射规则**，不是整张集合。

每条用例只回答一个问题：按映射表达式算出的这个字段，是否等于目标文档里的这个字段。业务键只用来把源文档和目标文档对齐，不断言笔数、漏键、多键、重复键、孤儿文档、作业重跑、失败恢复或 SLA。用户如果要整表对账或加载作业测试，明确说明那不在本 skill 里，不要顺便补上。

默认数据库是 MongoDB。查询使用 `mongosh` 聚合，不要写成关系型 SQL。源和目标在不同数据库时，`$lookup.from` 使用 `{ db: "<db>", coll: "<collection>" }`（MongoDB 5.1+）。

## 先拿到字段规则

按目标字段逐个收集。映射里没有的表达式不要编造，缺了就问：

- 目标字段全名（库、集合、字段）
- 源字段，以及这条规则还读哪些字段
- 映射表达式（直接赋值、清洗、计算、条件、查找、常量）
- 这条规则的分支：正常值、`null`、字段缺失、空字符串、未命中、`ELSE`
- 类型、小数位、舍入方式、时区
- 金额是 `Decimal128`、整数分，还是 `double`。`double` 必须写容差，不能直接 `$ne`
- 对齐用的业务键

过滤条件只作为“哪些文档适用这条字段规则”的前提，不要单独写成笔数用例。

## 用例模板

一个目标字段至少一条用例；规则有多个分支时，每个分支一条。

| 字段 | 写什么 |
| --- | --- |
| 用例 ID | `TC_<字段>_<分支>`，例如 `TC_CITY_TRIM` |
| 目标字段 | 只写被测字段 |
| 规则分支 | 正常值 / 空白 / null / 缺失 / 边界 / 查找未命中 / 某个条件分支 |
| 映射表达式 | 只描述这一个字段 |
| 源输入 | 该分支下，规则读到的源字段值 |
| 期望值 | 只给这个目标字段的期望值 |
| 步骤 | 聚合只投影业务键、`expected`、`actual` |
| 期望结果 | 该字段差异文档数为 0 |
| 实际结果 | 留空，执行后填 Pass / Fail |

## 编写规则

1. 输出按目标字段分组。每个字段先写表达式，再列分支用例。
2. 一条聚合只比较一个目标字段。不要在同一条 `$match` 里同时判断城市、金额和其他字段。
3. 失败结果只保留业务键、期望值、实际值。不要把整篇文档放进结果。
4. 设计数据时，一篇文档只为了触发当前分支，不夹带别的字段规则。
5. 已有数据做回归时，用同一条字段表达式逐文档重算，期望差异为 0。
6. 大集合用 `$lookup` 对齐，业务键要有索引。不要把字段值拉到应用内存里比对。
7. `null` 和字段缺失如果规则结果不同，分成两条用例。比较前用映射里的方式处理缺失，不要擅自 `$ifNull`。

字段比对骨架。把占位符换成这条规则的真实名称，`$project.expected` 里只放这个字段的表达式：

```javascript
db.getSiblingDB("<sourceDb>").getCollection("<source>").aggregate([
  { $match: <适用这条字段规则的文档> },
  { $lookup: {
      from: { db: "<targetDb>", coll: "<target>" },
      localField: "<businessKey>",
      foreignField: "<businessKey>",
      as: "t"
  }},
  { $unwind: "$t" },
  { $project: {
      _id: 0,
      key: "$<businessKey>",
      field: "<targetField>",
      expected: <这个字段的映射表达式>,
      actual: "$t.<targetField>"
  }},
  { $match: { $expr: { $ne: ["$expected", "$actual"] } } }
])
```

期望结果是 0 篇。

## 规则类型和要覆盖的分支

只为映射里真实存在的规则写分支。

### 直接赋值或改名

表达式是目标字段等于某个源字段。

- 普通值：原样落入目标字段
- 源为 `null`：目标字段也是 `null`
- 源字段不存在：按映射处理，不默认成空字符串

### 常量

不管源字段是什么，目标字段都是这个常量。用两个不同的源值证明结果不跟随源字段变化。

### 空值替换

- 源为 `null` 或缺失：目标字段变成规定的默认值
- 源有值：默认值不覆盖原值
- 空字符串：只有映射把 `""` 也当成空时才替换

### 字符串清洗

规则是 `trim`、大小写、去内部空白、替换字符时，每一种清洗单独证明。

- 首尾空白：清洗后的目标字段
- 大小写：按 `$toUpper` / `$toLower` 的结果
- 已经符合规则的值：保持不变
- `null`：保持 `null`，除非规则要求先替换再清洗

### 拼接、拆分、截取

- 参与拼接的字段都有值：分隔符和顺序与映射一致
- 其中一侧为 `null`：按映射跳过、保留分隔符，或整段变成 `null`
- 截取：刚好等于长度、短于长度、长于长度三个边界

### 类型转换

断言的是转换后的目标字段，不是“作业没有报错”。

- 合法字符串变成目标类型
- 小数位和整数范围没有丢精度
- 无法解析的值：目标字段按映射变成 `null`，或该字段走拒绝规则

日期字符串用 `$dateFromString`，数字用 `$toDecimal` / `$toInt` / `$toLong`，与映射的错误行为一致（`onError` / `onNull`）。

### 数值计算和舍入

表达式只重算这一个金额或数量字段。

- 正好落在舍入边界（例如保留两位时的 `x.xx5`）
- 负数
- 运算数有一个为 `null`：结果按映射为 `null` 或按 0 参与计算
- 金额字段用 `Decimal128` 重算。映射是 `Decimal128` 时，不要用 `double` 的 `$round` 代替

```javascript
expected: {
  $round: [
    { $multiply: [{ $toDecimal: "$amount" }, { $toDecimal: "$fx_rate" }] },
    2
  ]
}
```

### 日期、时区和业务日

只比较这个日期字段。

- 业务日界线两侧（时区午夜前后）
- 夏令时切换两侧
- 纯日期字符串与带时区的时间戳

`$dateTrunc` 或 `$dateToString` 的 `timezone` 必须写映射里的时区，不要默认服务器本地时间。

### 条件分支

映射里的每个 `WHEN` 一条用例，再加一条 `ELSE`。每条用例的期望值只属于那个分支，源数据要能排他地命中该分支。

### 查找

被测字段是查找写回来的描述、名称或代理键。

- 编码能命中：字段等于查找集合中的那一列
- 编码未命中：字段等于映射规定的默认值或 `null`
- 查找列本身为 `null`：不把“命中了文档”当成“字段有值”

### 聚合得到的字段

被测的是目标粒度上的这个度量字段，不是集合总笔数。按映射的分组键对齐，重算该字段的 `$sum` / `$avg` / `$min` / `$max`，只比较这个字段。

### 这个字段的约束

约束也落在单个字段上。

- 必填：该字段不为 `null` 且存在
- 值域：不在允许列表中的值为失败
- 格式：不符合该字段的正则
- 长度：源值长于该字段上限时，按映射截断或拒绝；断言截断后的字段值，或断言该字段没有被静默截断
- 范围：负数、未来日期、超过上下限时，该字段变成映射规定的值

查询直接在目标字段上过滤违规值，仍然不要扩展成整表质量扫描。

```javascript
db.getSiblingDB("<targetDb>").getCollection("<target>").aggregate([
  { $match: { <targetField>: null } },
  { $project: { _id: 0, key: "$<businessKey>", field: "<targetField>", actual: "$<targetField>" } }
])
```

### 这个字段在更新时怎么变

只有映射写了这个字段的更新规则才写。

- 覆盖：源字段变更后，目标里这个字段等于新值
- 版本化：这个字段是被跟踪属性时，当前版本的该字段等于新值，旧版本保留旧值
- 这个字段不被跟踪：源上改它不会新增版本，当前版本里该字段的值按映射保持或覆盖

不要把“整单是否只处理了变更行”写成用例。

## 示例

映射片段：

- `dw.fact_orders.city = upper(trim(src.orders.city))`
- `dw.fact_orders.amount_usd = round(decimal(amount) * decimal(fx_rate), 2)`
- 对齐键是 `order_id`
- 取消订单不在这两条字段规则的适用范围内

`city` 不和 `amount_usd` 写在同一条用例里。

`city` 的分支：

| 用例 ID | 分支 | 源 `city` | 期望 `city` |
| --- | --- | --- | --- |
| TC_CITY_TRIM | 首尾空白且小写 | `" paris "` | `"PARIS"` |
| TC_CITY_CLEAN | 已是清洗后的值 | `"PARIS"` | `"PARIS"` |
| TC_CITY_NULL | 源为 null | `null` | `null` |

`city` 的回归查询：

```javascript
db.getSiblingDB("src").orders.aggregate([
  { $match: { status: { $ne: "CANCELLED" } } },
  { $lookup: {
      from: { db: "dw", coll: "fact_orders" },
      localField: "order_id",
      foreignField: "order_id",
      as: "t"
  }},
  { $unwind: "$t" },
  { $project: {
      _id: 0,
      key: "$order_id",
      field: "city",
      expected: { $toUpper: { $trim: { input: "$city" } } },
      actual: "$t.city"
  }},
  { $match: { $expr: { $ne: ["$expected", "$actual"] } } }
])
```

`amount_usd` 单独再写一条，`expected` 只放舍入后的金额，`actual` 只取 `$t.amount_usd`。舍入边界用一笔 `amount * fx_rate` 正好为 `x.xx5` 的文档，不和城市用例共用断言。

## 输出格式

1. 按目标字段列出：字段名、表达式、对齐键、适用文档条件。
2. 每个字段一张分支表：用例 ID、分支、源输入、该字段期望值。
3. 每个字段一条只比较该字段的聚合。
4. 最后点名映射里还没给表达式的字段，不要用整表检查去填这些空缺。
